# Phase 2b — Telegram bot (2026-09-26)

Baseline: a0ece75 (deployed at CLOUD_URL). Spec overrides earlier docs where different.
Goal: one private bot for the single user — capture memos from any device, `/today` summary, a daily
digest (D-7/3/1 deadline + review reminders, today's tasks), and immediate critical-status alerts.

## 0. Env (all server-side; add to `.env.example` with comments, never print values)
- `TELEGRAM_BOT_TOKEN` — already in `.env.local` (user-provided).
- `TELEGRAM_CHAT_ID` — the user's private chat id; written by the setup script.
- `TELEGRAM_WEBHOOK_SECRET` — random 32+ chars `[A-Za-z0-9_-]`; generated by the setup script.
- Any of the three missing → every Telegram feature is a silent no-op; webhook route returns 503.

## 1. Pure logic (framework-free, unit-tested)
`lib/telegram/format.ts`
- `escapeHtml(s)` for Telegram `parse_mode: 'HTML'` (`& < >`).
- `formatCaptureReply(note, projectName|null)` → `메모 저장 ✓` + ` · @프로젝트` + ` #tag…`.
- `formatToday(input)` → `/today` message. Input: `{ today, checklist (me bucket from lib/logic/checklist),
  upcoming (lib/logic/upcoming, horizon 7), dayMemos (notes with date === today, not archived), statusItems }`.
  Sections (omit empty ones): `🔴 지연`, `📌 오늘`, `⏳ 7일 내 마감` (with `D-n`/`D-day`/`D+n` via `ddayLabel`),
  `📝 오늘 메모`, `⚠️ 상태` (critical/warn only). All empty → `오늘은 비어 있어요 ✨`. Max 30 lines total; overflow → `…외 n건`.
  End with a link line `대시보드: <CLOUD_URL>` when CLOUD_URL provided.
- `formatDigest(input)` → daily 09:00 message: `☀️ 9/26(토) 브리핑` header, then reminders (deadlines via
  `dueReminders` + reviews via new `reviewReminders`), then the same 지연/오늘 task sections, then critical status.
  Returns `null` when nothing to report (no message sent).
- `formatCriticalAlert(items)` → `🚨 <title> — <detail>` lines.
- `parseUpdate(update)` → `{ chatId, text } | null` (message / edited_message ignored → only `message`; non-text → null).
- `route(text)` → `{ kind: 'command', name: 'today'|'deadlines'|'help'|'start'|'unknown', arg } | { kind: 'capture', text }`.
  Commands may carry `@BotName` suffix (`/today@my_bot`). `/deadlines` = upcoming 14 days.

`lib/logic/upcoming.ts` — add `reviewReminders(reviews, today, days = [7, 3, 1])`: pending reviews
(invited/accepted, dueDate set) with dday overdue, 0, or in `days`. Same `UpcomingItem` shape. Tests.

`lib/logic/status-diff.ts` — `newCriticalItems(prev: StatusItem[], next: StatusItem[])` → critical items in
`next` whose `id` wasn't critical in `prev`. Tests.

## 2. Telegram client — `lib/telegram/client.ts` (server-only)
- `telegramConfig()` → `{ token, chatId, secret } | null`.
- `sendMessage(text, opts?)` → POST `https://api.telegram.org/bot<token>/sendMessage` `{ chat_id, text,
  parse_mode:'HTML', disable_web_page_preview:true }`, 5 s `AbortSignal.timeout`. **Never throws**; returns
  `{ ok: boolean, error?: string }`. Never log the token or the full URL.
- Messages > 4096 chars are truncated to 4000 + `…`.

## 3. Webhook — `app/api/telegram/webhook/route.ts`
- `POST` only. Verify header `X-Telegram-Bot-Api-Secret-Token` equals `TELEGRAM_WEBHOOK_SECRET` in constant
  time (reuse the compare in `lib/auth/bearer.ts`; export a helper if needed). Config missing → 503; bad
  secret → 401.
- `parseUpdate`; if `chatId !== TELEGRAM_CHAT_ID` → **200 with no reply and no write** (don't reveal the bot).
- capture → same path as `/api/capture` (`captureNoteInput` with projects + existing tags) but `source: 'telegram'`;
  reply `formatCaptureReply`. Factor the shared capture code into one function used by both routes.
- `/today` → `formatToday`; `/deadlines` → upcoming 14 days list; `/help`, `/start`, unknown → short Korean help
  (`메모는 그냥 보내면 저장돼요. @프로젝트 #태그 지원 · /today · /deadlines`).
- Always return 200 `{ ok: true }` after handling (Telegram retries non-2xx). Catch handler errors → reply
  `저장 실패: 잠시 후 다시 시도해 주세요` and still 200.
- Add `/api/telegram/webhook` to `proxy.ts` public paths.

## 4. Daily cron — extend `app/api/cron/daily/route.ts`
- After heartbeat: build digest; send if non-null and not already sent today.
- Idempotency: new `app_meta` key/value store. Migration `0003_app_meta.sql`: `create table if not exists app_meta
  (key text primary key, value jsonb not null, updated_at timestamptz not null default now())`, RLS on, revoke
  anon/authenticated (same as 0001). Repo: `getMeta<T>(key): Promise<T|null>`, `setMeta(key, value)` in both
  adapters (LocalRepo: `db.meta` record, tolerant loader default `{}`). Key `telegram:digest:lastSent` = `'YYYY-MM-DD'`.
- `?force=1` (still requires CRON_SECRET) bypasses the once-per-day guard — for manual testing.
- Response: `{ ok, at, digest: 'sent'|'skipped-empty'|'skipped-already'|'disabled'|'failed' }`. A Telegram failure
  never fails the cron (heartbeat must stay green).

## 5. Critical alerts — extend `app/api/ingest/route.ts`
- Before writing the new snapshot, read the previous one; `newCriticalItems(prev, next)`; if any → `sendMessage(
  formatCriticalAlert(items))` (fire and await with the 5 s cap; failure ignored). Ingest response unchanged
  except optional `alerted: n`.

## 6. Setup script — `scripts/telegram-setup.mjs` (plain JS, Node ≥18, reuse `scripts/lib/env.mjs`)
1. Load `.env.local`; require `TELEGRAM_BOT_TOKEN`, `CLOUD_URL`.
2. `getMe` → print `@username` only. 401 → print "토큰이 올바르지 않습니다 (BotFather에서 다시 확인)" and exit 1.
3. If `TELEGRAM_CHAT_ID` absent: `deleteWebhook` (getUpdates doesn't work while a webhook is set), `getUpdates`,
   pick the most recent **private** chat; none → print "봇에게 아무 메시지나 보낸 뒤 다시 실행하세요" and exit 1.
   Append `TELEGRAM_CHAT_ID=` to `.env.local` (print only the last 3 digits).
4. If `TELEGRAM_WEBHOOK_SECRET` absent: generate (crypto.randomBytes → base64url, 32 bytes) and append.
5. `setWebhook` `{ url: CLOUD_URL + '/api/telegram/webhook', secret_token, allowed_updates:['message'],
   drop_pending_updates: true }`; `setMyCommands` (today: 오늘 할 일·마감 요약, deadlines: 14일 내 마감, help: 사용법).
6. `--vercel` flag: push `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_WEBHOOK_SECRET` to Vercel production env
   via `npx vercel env add <NAME> production` with the value on stdin and `--token` from VERCEL_TOKEN
   (remove-then-add if it exists). Never echo values.
7. `--send-test`: sendMessage `✅ Command Center 봇 연결됨`.
Add `npm run telegram:setup`. Document in `docs/SETUP.md` (Korean, short) and CLAUDE.md phase status.

## 7. Tests / acceptance
- vitest: format functions (escaping, empty/overflow, D-labels), route(), parseUpdate(), reviewReminders,
  newCriticalItems, webhook handler pure part (wrong chat → no write; bad secret → 401; capture → note with
  source 'telegram'), cron digest idempotency with a fake repo + fake sender (inject sender for testability).
- Isolation gate passes (no personal strings in tests — use fictional names/ids).
- typecheck, lint, tests, build pass.
- Live (only if the token is valid — `getMe` ok): run migration 0003 (`npm run db:migrate`), deploy, then
  `node scripts/telegram-setup.mjs --vercel --send-test`, redeploy so env applies, then GET the cron with
  `?force=1` and report the `digest` field. If the token is invalid, stop after deploy and report — the planner
  will finish setup once the user fixes the token.

## 8. Rubric
1. Only the configured chat can write or read anything; other chats get silence.
2. Webhook secret verified in constant time; tokens never logged/printed.
3. Telegram failures never break capture, cron heartbeat, or ingest.
4. Digest at most once per KST day (unless force); empty → no message.
5. Critical alerts fire only on newly-critical items (no hourly repeats).
6. Capture path shared with `/api/capture` (one implementation).
7. Node 18-compatible setup script.
