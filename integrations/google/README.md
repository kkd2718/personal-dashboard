# Google 연동 (Apps Script)

Command Center 앱에는 Google OAuth 클라이언트가 없습니다. 대신 **각 Google 계정 안에서
직접 실행되는 Apps Script**가 캘린더 일정과 리뷰어 메일 후보를 앱의 `POST /api/google/sync`
로 보내는 방식입니다 (단방향, 계정당 1개 스크립트).

여러 계정(개인 Gmail, 랩 계정 등)에 리뷰 초대가 흩어져 있을 수 있으므로, **계정마다 이
스크립트를 따로 설치**하고 `ACCOUNT` 속성만 다르게 설정하세요.

## 1. 스크립트 설치

1. 동기화하려는 Google 계정으로 로그인한 상태에서 https://script.google.com 접속
2. **새 프로젝트** 생성
3. `Code.gs`의 내용을 전체 복사해서 붙여넣기 (기본 `myFunction()` 내용은 지우기)
4. 왼쪽 톱니바퀴(프로젝트 설정) → **스크립트 속성** → 아래 값 추가:

   | 속성 | 값 | 설명 |
   |---|---|---|
   | `CC_URL` | `https://your-app.vercel.app` | 배포된 앱 주소 |
   | `CC_TOKEN` | `.env.local`의 `GOOGLE_SYNC_TOKEN` 값 | 모든 계정 스크립트가 같은 토큰 사용 |
   | `ACCOUNT` | `main` 등 짧은 라벨 | 계정 구분용 (아래 "여러 계정" 참고) |
   | `CALENDAR_IDS` | (선택) 쉼표로 구분한 캘린더 ID, 기본 `primary` | 아래 "캘린더 ID 찾는 법" 참고 |
   | `GMAIL_QUERY` | (선택) Gmail 검색어 | 기본값은 `Code.gs` 상단 주석 참고 |
   | `DAYS_BACK` | (선택) 기본 `7` | 과거 며칠치 일정을 가져올지 |
   | `DAYS_AHEAD` | (선택) 기본 `60` | 앞으로 며칠치 일정을 가져올지 |

5. 함수 선택 드롭다운에서 `setup` 선택 → **실행**
6. 처음 실행하면 권한 승인 화면이 뜹니다 (캘린더/Gmail 읽기, 외부 URL 호출) → 본인 계정이므로
   승인해도 안전합니다
7. 실행 로그(보기 → 실행 기록)에서 `HTTP 200`이 찍히면 성공. 이후 매시간 자동 실행됩니다
   (`setup`이 트리거를 idempotent하게 설치 — 여러 번 실행해도 트리거가 중복되지 않음)

## 2. 여러 계정에 설치하기

리뷰 초대 메일이나 리비전(수정 요청) 메일이 다른 계정으로 올 수도 있으므로, 그 계정으로도
로그인해서 위 과정을 반복하세요. 예:
- `ACCOUNT=main` — 주 계정. 리뷰어 초대가 여기로 옴
- `ACCOUNT=amc` — 지도교수가 본인 논문의 리비전(수정 요청) 메일을 전달해주는 계정

이때:
- 같은 `Code.gs`를 그대로 복사
- `CC_TOKEN`은 동일하게 사용
- `ACCOUNT`만 다르게 설정

앱은 `account` 값으로 일정/후보를 구분하므로, 한 계정을 재동기화해도 다른 계정 데이터는
지워지지 않습니다. 리비전 메일은 제목/본문에 decision·revision·revise·수정 관련 단어가
있으면 기본 `GMAIL_QUERY`에 걸립니다 — 지도교수가 전달(Fwd:)하는 메일도 원본 내용이 본문에
포함되어 있으면 그대로 파싱됩니다.

알림 규칙:
- 두 계정 모두 리뷰 초대·마감 알림·리비전 레터를 똑같이 인식합니다. 같은 레터가 양쪽에 오면(저널 → 한 계정,
  교수님 전달 → 다른 계정) 원고번호(없으면 Fwd:/Re:를 뗀 제목)로 한 번만 후보가 됩니다.
- MDPI(`mdpi.com`) 리뷰 메일은 서버 파서에서 제외됩니다. 본인 논문의 MDPI 리비전 레터는 인식됩니다.
- 휴지통으로 옮긴 메일은 "처리함(거절 후 삭제)"으로 보고, 대기 중인 후보를 자동으로 무시 처리합니다.
- 텔레그램 즉시 알림은 리비전 요청과 수락한 리뷰의 마감 알림만 보냅니다. 리뷰 초대는 대시보드의
  "메일 확인" 칩에만 표시됩니다.
- 구글 캘린더에 마감 표시: **메인 계정(`ACCOUNT=main`) 스크립트에만** 속성 `WRITE_DEADLINES` = `true`를 추가하면, 대시보드의
  미완료 마감(리비전 제출 등)과 수락한 리뷰 마감일이 기본 캘린더에 종일 일정으로(분류별 이모지: 논문 📝 · 리뷰 🔍 · 과제 💰 · 학위 🎓 · 면접 🎤, 그 외는 이모지 없음) 생기고, 완료하거나 지우면
  다음 동기화 때 사라집니다. 설명에 `[CC:...]` 표시가 있는 일정만 건드립니다.
- "Thank you for your review" 메일은 `리뷰 제출 완료`로 인식되고, 추가하면 같은 원고번호의 리뷰가 제출됨으로 바뀝니다.

### 근무표 (선택)

공유 구글 시트(월별 `YY.MM` 탭)에서 **내 근무만** 가져와 캘린더/홈/텔레그램에 표시합니다.
`main` 계정 스크립트에만 속성을 추가하세요. 구글 캘린더에는 아무것도 쓰지 않습니다.

| 속성 | 값 | 설명 |
|---|---|---|
| `WORK_SHEET_ID` | 시트 ID (스크립트 속성에만 저장) | 비워 두면 근무표 동기화 없음 |
| `WORK_NAME` | 시트에서 내 행의 이름 칸과 똑같은 텍스트 | 이 이름의 행만 읽음 |
| `WORK_MONTHS_BACK` | (선택) 기본 `1` | 이번 달 기준 몇 달 전 탭부터 읽을지 |

개인정보: 시트에는 다른 사람의 이름과 일정이 있지만, 스크립트는 **내 행 하나**에서
`{날짜, 코드}` 쌍만 서버로 보냅니다. 이름(`WORK_NAME`)과 다른 행은 전송/로그/DB에 남지 않고,
시트 ID와 이름은 저장소 코드·문서·테스트에 넣지 않습니다.

## 3. 캘린더 ID 찾는 법

Google Calendar 웹 → 왼쪽에서 캘린더 이름에 마우스 오버 → 점 3개 → **설정 및 공유** →
"캘린더 통합" 섹션의 **캘린더 ID** 값을 복사. 본인 기본 캘린더는 `primary`로 충분합니다.
여러 캘린더를 합치려면 `CALENDAR_IDS`에 쉼표로 나열하세요
(예: `primary,ko.south_korea#holiday@group.v.calendar.google.com`).

기본 동기화 대상은 **main 계정의 기본(primary) 캘린더 + 한국 공휴일 + 지도교수님 캘린더**입니다.
지도교수님 캘린더를 공유받았다면(공유 캘린더 → 캘린더 ID 확인), 그 ID를 `main` 계정 스크립트의
`CALENDAR_IDS`에 쉼표로 추가하세요. 대시보드 캘린더 화면에서 공휴일을 제외한 각 캘린더는
기본적으로 꺼져 있고(primary만 기본 켜짐), 헤더의 캘린더 이름 칩을 눌러 원하는 캘린더만
켤 수 있습니다 (설정은 서버에 저장되어 기기 간에 공유됩니다).

## 4. 중지하려면

Apps Script 편집기에서 함수 선택 드롭다운에서 `teardown` 선택 → 실행. 시간 기반 트리거가
모두 삭제됩니다 (스크립트 자체와 속성은 남아 있으니, 다시 시작하려면 `setup`을 다시 실행).

## 참고

- 이 스크립트는 메일 본문 전체를 보내지 않습니다 — 앱 서버가 파싱에 필요한 필드와 최대
  4000자까지만 받아서, 저장 시엔 그마저도 파싱된 필드 + 300자 스니펫만 남기고 버립니다.
- 토큰이나 메일/일정 본문은 실행 로그에 출력되지 않습니다 (HTTP 상태 코드만 기록).
